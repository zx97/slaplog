# Sample reports

Two complete HTML reports, generated by slaplog, show what the tool produces
and how a report reads.

| File | Origin | Reproducible |
|---|---|---|
| [`slaplog-sample.html`](slaplog-sample.html) | synthetic log | yes |
| [`slaplog-incident-sample.html`](slaplog-incident-sample.html) | a simulated incident | no (snapshot) |

Both contain only reserved names: `example.com` / `example.org` /
`example.net` (RFC 2606) and RFC 5737 addresses (`192.0.2.0/24`,
`198.51.100.0/24`, `203.0.113.0/24`). No production identity, hostname,
address or directory content appears in either.

---

## 1. Synthetic sample (reproducible)

[`slaplog-sample.html`](slaplog-sample.html) is generated from a small
synthetic log. The log spans four days and tells a small incident story:

- `portal`, `monitor`, `legacy-app` and `admin` run normally;
- `hr-sync` bursts heavily at 02:00–03:00 every night;
- on **2026-09-16 10:00** a new service, `reporting`, starts and becomes the
  busiest consumer, running expensive substring and negated searches.

The report picks this up:

- **Top Consumer per Hour** — the bars turn from green/orange to blue at
  10:00 on 16 September;
- **Consumers Over Time (stacked)** — how each hour's total load is split;
- a vertical **onset** marker at 2026-09-16 10:00 on both charts, with a
  tooltip explaining it;
- a **resource hog** verdict for the unindexed filter family.

### Files

| File | Purpose |
|---|---|
| `slaplog-sample.html` | The generated report — open it in a browser. |
| `access.log.gz` | The synthetic log it was generated from. |
| `make_sample.py` | Deterministic generator (seed 42). |

### Regenerate

From this directory:

```sh
python3 make_sample.py access.log
gzip -9 -c access.log > access.log.gz
../../slaplog access.log.gz -o html \
    --title "slaplog sample (synthetic data)" \
    > slaplog-sample.html
```

The generator is deterministic, so the same log — and the same report — come
back on every run.

## 2. Simulated sample

[`slaplog-incident-sample.html`](slaplog-incident-sample.html) is a report
generated from a simulated OpenLDAP log set, then **fully anonymised**: every
account, host, domain, IP address, e-mail, group and custom schema value was
replaced with a synthetic value, and the custom schema attribute names were
renamed (`customAttr1`, `customAttr2`, …). The numbers, charts, tables and the
**shape of the incident** are simulated; only the labels are synthetic.

Three display adjustments make the sample easier to read and more readable:
the dates are shifted by six months, two days and 17:23:12 (the report's
"Generated" date is kept), `slapo-sock` filter messages become
`slapo-sock filter rule #<n>`, and oversized filters are shortened.

It is here to show what the report makes obvious at a glance — the kind of
diagnosis that would otherwise take hours of reading raw log lines:

- **Statistics** — the time range, the slowest operations, the top consumer.
- **Top Consumer per Hour** — the bars turn to one account's colour and stay:
  the takeover is visible without reading a single log line.
- **Resource Hog** — the unindexed filter family that dominates the cumulative
  `etime` is named outright.
- **Generalized Search Filter Families** — one template covers thousands of
  operations: the enumeration is one row, not thousands.
- **Response Time Distribution** — the shift of operations into the seconds.
- **Consumers Over Time (stacked)** — how each hour's total load is split.

The report is a snapshot: it cannot be regenerated without the source material,
which is not part of this repository.
